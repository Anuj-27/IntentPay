How it works

One pipeline, seven deterministic checkpoints.

The LLM only extracts intent. Everything that follows is deterministic backend logic — the same code path runs whether the tool below is used, the assistant chat is used, or a screenshot is dropped in.

  1. 01
    Intent Mandate

    Natural language becomes a structured, machine-verifiable request.

  2. 02
    Catalog match

    Only active, in-stock products from approved merchant contracts qualify.

  3. 03
    Hard constraints

    Budget, brand, and category rules filter the catalog before anything is ranked.

  4. 04
    Trade-off engine

    Meaningful price/value upgrades stay visible to you — never automatic.

  5. 05
    Proposed Purchase

    The exact product, quantity, and total are locked in for verification.

  6. 06
    Trust Gate

    Intent verification and merchant policy resolve to one decision: ALLOW, REASK, BLOCK, or ESCALATE.

  7. 07
    Payment boundary

    Only ALLOW reaches the internal simulator or the Razorpay Test Mode adapter.

Trust & safety

Every AI money action is explainable.

An agent may propose a purchase. Only deterministic, user-authorized, policy-compliant code can release it to a payment provider.

ALLOW

Budget, quantity, subscription, and merchant policy all check out.

REASK

A meaningful trade-off or an above-budget option needs your renewed input.

BLOCK

An explicit restriction — like “no subscription” — was violated.

ESCALATE

Your intent is valid, but merchant policy requires human approval.

Rules that never bend

  • Budget permission is a maximum, not a spending target.
  • Hard constraints cannot be silently overridden by ranking.
  • Recommendation permission is not payment authorization.
  • A timeout is uncertainty, not proof that payment failed.
  • Duplicate logical requests cannot create duplicate financial effects.
